# Service templates

The [systemd units](systemd/) and [launchd plists](launchd/) run the daemon and the optional cc-connect adapter as separate services. Replace every `/path/to/...`, user, group and provider placeholder before installing. Use dedicated unprivileged service accounts and install the binaries and service definitions in administrator-controlled locations.

- Initialize a new database with `ink state init --data STATE_DIR` as the daemon user before the first start. For systemd the default state path is `/var/lib/ink-commons` (`%S/ink-commons`), and the unit enforces mode `0700`. For launchd, create the configured state directory with mode `0700` and ownership matching the daemon account. Use a short absolute path to stay within the Unix socket path limit. The daemon creates `ink.sock` with mode `0600`. Run local CLI commands as the daemon user with the same `--data` or `INK_DATA_DIR`.
- Keep daemon and adapter environment files separate. On systemd, use `EnvironmentFile` assignment syntax and root-owned files with mode `0600`. On launchd, use trusted POSIX shell assignments in files readable only by the respective service account. The plist sources that file as the service user and exports the assignments before executing the binary. Keep secrets in these files.
- To use the adapter, configure its environment with `INK_CC_CONNECT_URL` and `INK_ADAPTER_TOKEN`, plus `INK_CC_CONNECT_TOKEN` or `INK_DISCORD_TOKEN` when needed. Configure the matching daemon provider to use `http://127.0.0.1:8788/v1/execute` with the same token in its configured `token_env`. Keep the adapter listener on loopback. The adapter needs no access to the daemon state directory or socket.
- Install systemd units in the system unit directory, run `systemd-analyze verify` on the rendered units, then reload the manager and enable the services you use. Install launchd templates as root-owned system LaunchDaemons with mode `0644`, use `plutil -lint` on the rendered plists, then bootstrap them in the system domain. For a staged cutover, use `ink serve --config-only` or add `--poll-gate` with an absolute gate-file path.
